{% comment %}Included in base.html, so every page that extends it records exactly one view. A page that is somebody looking at an auction says so from its *view*, by putting ``page_view_auction`` (and ``page_view_lot``) in the context. Three do: the auction's rules page, its lot list, and a lot page. That list is the definition of Auction.unique_views -- "distinct visitors who viewed this auction's rules page or any of its lots" -- which organizers read on their own stats page, so the bidder list, the stats page and the edit form must not tag, even though all three have an `auction` in context. Reading the tag off whatever `auction` happens to be in scope would quietly fill an organizer's traffic number with their own admin visits. A lot page sends the auction too, not just the lot. Rows written before 2026-09-09 carry only the lot, which is why the readers of this data still match an auction as `auction_id OR lot_number__auction_id` -- an OR across a join, and the shape behind the July database incident. tasks.backfill_page_view_auctions is walking those rows in the background so that can go. auctions/test_page_view_beacon.py is the ratchet for all of it.{% endcomment %}
