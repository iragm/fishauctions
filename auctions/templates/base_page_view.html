{% comment %}Included in base.html, so every page that extends it records exactly one view. A template that knows which lot or auction its page is about calls pageView with that pk from a parse-time script; that call *replaces* the automatic one rather than adding a second row, because the first call of either kind wins. That is why an enriched call has to run while the page is parsing. Made from a load handler it arrives after the automatic view has already gone, and the row lands with both FKs null -- which is invisible to every organizer-facing report, since they all filter on one of those two columns. auctions/test_page_view_beacon.py is the ratchet for that ordering.{% endcomment %}
