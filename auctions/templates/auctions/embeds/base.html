{% comment %} The shell every styled club embed uses: an admin pastes an iframe of one of these into WordPress, Wix or Squarespace and it has to look like it belongs there without knowing anything about the page it lands on. So the CSS lives here once, in four blocks — a light palette, a dark palette, a card, and a list — and each embed only supplies its rows. Four rules this file exists to enforce: * **Nothing but the rows.** No heading, no "More from" link, no club name. This is pasted into a page that already has its own heading and its own navigation, and a club that wanted a link back here would have written one; ours reads as somebody else's furniture in their room. * **One palette.** Embeds that each carried their own copy of these variables drifted apart the first time one of them was touched, and a club that used two of them got two slightly different greys on the same page. * **No external requests.** No web fonts, no stylesheet, no fetched script. This renders inside somebody else's site, often over a slow connection, and anything it fetches is another thing that can fail in public. The one script here is inline, is a dozen lines, and fetches nothing. * **It measures itself and says so.** An iframe is the one box on a page that cannot size itself to its contents, so a snippet pasted with height:880px for ten events shows two events and 700 pixels of nothing. The script at the bottom posts this document's real height to whoever framed it, and the snippet on the website-integration page pastes a two-line listener alongside the iframe. Both halves are optional in the sense that matters: no parent, no message; a listener stripped by a CMS leaves the fixed height, which is exactly what a club has today. `embed_mode` is "light" or "dark" and is picked by the ?format= the club chose, not by the visitor's system setting — the club knows what colour its own website is and we do not. {% comment %}Tell the framing page how tall this really is, so it can shrink the iframe to fit. Posted to "*" because we cannot know what site framed us, and safe to: the only thing in the message is a number of pixels that is already visible to anyone who can see the frame. The listener on the other end matches on event.source, so a page carrying several of these gives each iframe its own height. ResizeObserver covers a narrow phone re-wrapping a long announcement; the load handler covers the first paint. The height is repeated rather than only sent when it changes, because the listener is on the other side of a race we cannot see: it is registered while the framing page parses, and a page that defers its inline scripts, restores this frame from the back/forward cache or reveals it from a tab registers it after our first message has already gone. A missed message is an iframe stuck at the height somebody guessed months ago, with nothing anywhere saying why, so `force` re-sends the same number on load and once a second later. Everything else still de-duplicates on `last`: a resize that changes nothing costs no message.{% endcomment %} {% endautoescape %}
