{% comment %} One "put this on your website" block, rendered from a dict built by ClubWebsiteIntegrationView. Expects `snippet` with: title, icon, blurb, url, heights (a {count: pixel height} map), available, unavailable_reason, settings_url, and counts/max_count for the ones that take a ?count=. Each snippet is an iframe **and** a two-line listener, in one block, because an iframe is the one box on a page that cannot size itself to its contents: a height picked for ten events shows two events and 700 pixels of nothing under them. The embed measures itself and posts its height; the listener sets it. Pasting both is one copy either way, and a CMS that strips the script leaves the height attribute doing what it always did. The listener names **no host**. It finds the iframe whose `contentWindow` is the message's source -- which nothing can forge, and which is what keeps each of several embeds on one page sizing itself -- and then checks `e.origin` against that iframe's own `src`. The first version baked this site's origin into the script, and the failure was silent in exactly the case that happens: a snippet copied from one host with the iframe pointed at another (staging to production, a club moving domains) went on listening for messages that never came, resized nothing, and gave nobody anything to look at. A check the snippet derives from itself cannot be copied out of step. A snippet carrying `links` instead is the other kind: plain addresses rather than an iframe, for the things a club's own site already knows how to present (a "subscribe" button in their menu). It shares this card so the heading, the blurb and the switched-off note read the same either way. Everything is spelled out rather than generated by JavaScript, because the thing being handed over is text somebody copies into WordPress: a "copy" button that fails silently on an old browser leaves them with nothing, where a visible 
 always works.

spread one over two lines and it renders straight onto the page.
