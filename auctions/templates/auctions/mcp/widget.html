{% comment %} The one document behind every ui:// resource this server publishes: an MCP host fetches it with resources/read, mounts it in a sandboxed iframe, and pipes the tool's own result into it. It is one template rather than five because the five widgets differ only in which renderer runs — `view` is baked in by auctions.mcp.widgets at read time, and the JS switches on it. Five documents would be five copies of the palette, the theming and the 330 KB runtime, which is exactly the drift auctions/templates/auctions/embeds/base.html was written to prevent for the club embeds. The palette is that file's, deliberately: this is the site's second "HTML that has to look right somewhere that isn't our page", and having two of them differ would be a mistake we have already made once. What is new here is host theming — a club picks light or dark for its own website, but a Claude user's theme is theirs, so the host tells us and we follow. Nothing is fetched. Not the runtime (inlined below), not a font, not a stylesheet, not an image whose bytes we did not put in the payload — the iframe's CSP blocks all of it, and a widget that half-loads is worse than one that never tried. Outbound links go through app.openLink(); the sandbox drops window.open and target="_blank" on the floor. {% endcomment %}{% autoescape on %} {{ widget_title }}
