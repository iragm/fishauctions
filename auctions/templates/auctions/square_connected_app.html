The app runs seller onboarding in ASWebAuthenticationSession (Chrome Auth Tab on Android), which is watching for its callback scheme and closes itself the moment it sees one. The scheme is deliberately ``fishauctions-oauth://`` and NOT the app's own ``fishauctions://``. Nothing registers ``fishauctions://`` with the OS -- the shell only ever sees it inside its own WebView, via shouldOverrideUrlLoading -- and that decision stands. Only a pending auth session can act on ``fishauctions-oauth://``, which is exactly the lifetime this page needs. Copy has to be platform-neutral: request.is_ios_app / is_android_app are both false here, since that browser sends Safari's (or Chrome's) User-Agent -- which is why _done keys off session_opened_by_app instead.
